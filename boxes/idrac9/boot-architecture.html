Virtual iDRAC9 — how the boot is wired

One firmware file becomes a running Dell BMC under QEMU. The spine is the boot data-flow; the two coral nodes are where the real engineering lives — a gdb-found kernel patch, and the custom /init we substitute to control the whole machine.

THE LEVER

Custom /init

  • Kernel cmdline is locked to init=/init
  • /init lives in the initramfs — which we own
  • So we never patch the boot path; we replace it
  • It mounts the rootfs & masks Dell's watchdogs

THE GDB WORK

Patched kernel

  • dm_bufio 30s timer panicked at ~31.8s
  • gdb read the live work_struct → found it
  • NOP'd 2 instructions, booted as uImage
  • Single-CPU DTB kills the per-cpu crashes

THREE WAYS TO RUN

Phase 1 / 2 / 3

  • ./run.sh — shell, chroot, run binaries
  • ./run-p2.sh — full systemd + daemons
  • ./run-p3.sh+ssh-in.sh — SSH root login
  • next: daemon mesh → racadm + live RAKP
